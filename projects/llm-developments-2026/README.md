## Goal

Convert the broad 2026 paper list into a small number of production-relevant experiment lanes.

## End state

This track is successful when the repo contains:

- one retrieval experiment lane for lexical, vector, and hybrid search in agent harnesses — **built** (`retrieval_mode`)
- one context-management lane for repo instructions, context compaction, and file-pointer result delivery — **built** (`context_policy`, `instruction_mode`)
- one reasoning-control lane for verifier loops and test-time scaling — **built** (`verifier_enabled`, `candidate_count`, `share_evidence`, `max_retries`)
- one long-horizon CLI benchmark lane for coding-agent tasks — **partial** (scenario pack + stage-level eval + scorecards in `corpus.py`/`scorecard.py`; long-horizon multi-step chains still to add)
- one long-context systems lane for cache, compression, and history-selection prototypes — **deferred** (some prototypes already live in `code/architecture-advances-2026/`)
- one final memo that says which ideas are worth carrying into the default harness — **built** (`experiment-findings.md`, regenerated by `llm-dev-memo`)

## Current findings (deterministic synthetic benchmark)

- Lexical/grep is a strong default; vector only earns its cost on paraphrase-heavy queries; hybrid adds robustness at ~2x retrieval ops.
- Full inlining maximizes evidence recall; snippet and pointer delivery cut tokens but drop tail-placed evidence — pointer craters honest success.
- Hierarchical repo instructions unlock guidance-gated tasks (67% → 83%) at ~35 tokens/task.
- A grounding verifier removes shipped hallucinations (17% → 0%) by escalating instead of bluffing.
- Multi-attempt / retry recovers flaky-recall tasks (67% → 75%); the stacked production candidate reaches 100% honest success at higher latency.

See `experiment-findings.md` for the full memo. Numbers test policy *direction*, not absolute production quality.

## Working rule

This track should not become a giant survey rewrite.

Each promoted paper must lead to one of:

- a harness change
- an eval change
- a reasoning-control change
- a long-context systems prototype

If a paper does not change build decisions, it stays background reading.
